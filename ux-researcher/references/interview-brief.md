# Interview brief

Assembles the front-end work into a runnable document: who, why, and the guide itself with a timed arc. Pull the hypothesis from `method-selection.md`, the questions from `question-bank.md`, and run the draft through `bias-audit.md` before finalizing.

## The arc

A good interview moves from broad and easy to specific and harder, then back out. Front-load nothing sensitive. Map the core block directly to the hypotheses so every question earns its place.

1. **Warm-up (3 to 5 min).** Build rapport, set context, get consent and recording. Low-stakes, easy questions. Establishes that there are no wrong answers.
2. **Context (5 to 10 min).** Grand-tour questions about their world and current behavior. Sets the frame before you probe.
3. **Core (20 to 30 min).** One sub-block per hypothesis. Incident-based questions plus probes. This is where the study lives.
4. **Deep dive (5 to 10 min).** Follow the most interesting thread that emerged. Where the unexpected insight usually hides.
5. **Wrap (3 to 5 min).** Magic-wand question, "anything I should have asked?", thanks, next steps.

Budget for a 45 to 60 minute session. Roughly 8 to 12 core questions; the rest of the time is probing.

## Quality gate before sending

- Every core question maps to a hypothesis. Cut any that does not.
- Run the full set through `bias-audit.md`.
- No question predicts the future or asks for opinions where an incident would do.
- Sensitive and demographic items are last, with non-answer options.
- A colleague who has not seen the project could run it from the document alone.

## Output format for this mode

Deliver the filled template. Flag any section where you made an assumption (for example, you inferred the participant profile from context). Offer to generate the screener separately if recruitment is in scope.
